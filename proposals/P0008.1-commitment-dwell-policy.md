# P0008.1: Commitment / Dwell Policy

**Status**: Implemented
**Date**: 2026-08-16
**Depends on**: P0008

> **Hardware validation: Pending** — Scenario A/B/C（person 20min HOLD / new-object SWITCH / person-leave RELEASE）尚未在硬件上验证。单元测试 19/19 通过，但 P0008.1 尚未在行为层面 validated。

## Objective

P0008.1 解决当前主动观察 Runtime 的一个明确行为缺口：

> 系统已经能够决定“接下来去看什么”，但不能稳定决定“当前目标应该继续看多久”。

当前 `Curiosity` 主要回答“是否值得切换到新的目标”；它不应同时承担“当前目标是否值得持续关注”的职责。

本阶段新增一个轻量级 **Commitment / Dwell Policy**，作为当前目标与 challenger target 之间的仲裁层，输出仅限：

```text
HOLD
SWITCH
RELEASE
```

不修改 Curiosity、Familiarity、Role、Mission 的既有职责。

---

## Background

当前实验已经验证：

```text
Attention spans ≈ 499
平均持续 ≈ 24s
```

主要离开原因：

```text
explore   ≈ 42%
switched  ≈ 41%
idle_timeout ≈ 14%
```

同时：

```text
lost = 0
hot_timeout = 0
```

说明系统多数情况下不是因为目标消失而离开，而是主动切换或进入探索。

代码审计进一步确认：

```text
Curiosity =
interest
× uncertainty
× freshness
× (1 - familiarity)
× role
- movement_cost
```

对于持续存在且高度熟悉的人：

```text
freshness → 0
uncertainty → 0
familiarity → 1
```

因此：

```text
curiosity → 0
```

这对于“是否需要重新探索这个人”是合理的。

但 Runtime 当前把：

```text
低 curiosity
```

隐式等价为：

```text
不值得继续看
```

这是错误的职责耦合。

---

## Architecture

当前：

```text
Current Target
      │
      └──────────────┐
                     ▼
Curiosity / Anchor Stay
                     │
                     ▼
                    PTZ
```

P0008.1 调整为：

```text
Current Target ──→ Commitment ───────┐
                                     │
New Candidate ──→ Curiosity ─────────┤
                                     ▼
                              Dwell Arbiter
                                     │
                        ┌────────────┼────────────┐
                        ▼            ▼            ▼
                       HOLD        SWITCH       RELEASE
                                     │
                                     ▼
                                    PTZ
```

关键原则：

```text
Curiosity = "新的目标值得去看吗？"

Commitment = "当前目标还值得继续看吗？"
```

---

## Design

### 1. Commitment State

为当前 active observation target 维护轻量状态：

```python
CommitmentState:
    entity_id
    started_at
    last_confirmed_at
    hold_score
    target_class
```

不持久化。

不跨 Session。

目标切换或释放后销毁。

---

### 2. Commitment Inputs

Commitment 只能消费现有 Runtime 信号，不新增新的感知模型。

建议输入：

```text
current_entity
elapsed_attention
last_confirmed_at
track_hit
entity.role_weight
mission_boost
entity.interest
entity.familiarity
challenger_curiosity
```

其中：

* `role_weight` 表示当前角色是否关心该类目标；
* `mission_boost` 表示当前 Persona/Mission 是否额外关注；
* `track_hit` 表示当前目标是否仍被持续确认；
* `elapsed_attention` 表示已经投入多少观察时间；
* `challenger_curiosity` 表示新目标的竞争强度。

---

### 3. Commitment Score

第一版必须保持简单且可解释。

建议不要直接复用 Curiosity 公式。

可以采用：

```text
commitment_score =
role_component
+ mission_component
+ presence_component
- disengagement_component
```

其中：

```text
role_component:
当前 entity 的 effective role

mission_component:
当前 mission boost

presence_component:
最近持续 track/confirm 则增加

disengagement_component:
长时间无 track hit / entity lost / timeout
```

注意：

**Familiarity 不作为负项直接压低 Commitment。**

原因：

```text
熟悉 != 不值得陪伴
```

例如：

```text
主人 familiarity 很高
但 commitment 仍应可以很高
```

---

### 4. Dwell Arbiter

新增统一仲裁函数：

```python
decide(
    commitment_score,
    challenger_curiosity,
    current_entity_status,
    elapsed_attention
) -> HOLD | SWITCH | RELEASE
```

语义：

#### HOLD

当前目标仍存在，且 commitment 足够高。

即使 challenger curiosity 略高，也保持当前观察。

#### SWITCH

新目标的 curiosity 明显高于当前 commitment。

允许切换。

#### RELEASE

当前目标已经：

* LOST
* 长时间无法确认
* commitment 降到最低
* 已达到必要的安全上限

释放目标，允许进入 explore。

---

### 5. Hysteresis / Switch Margin

禁止：

```text
challenger_curiosity > commitment
→ 立即 SWITCH
```

否则会重新产生抖动。

需要最小 switch margin，例如：

```text
SWITCH only if:

challenger_curiosity
>
commitment_score + SWITCH_MARGIN
```

`SWITCH_MARGIN` 作为单一可解释配置项。

不要引入复杂多参数 tuning。

---

### 6. Persona Integration

P0008.1 可以读取 Persona 中已经存在的行为字段，但不要扩展复杂 schema。

例如：

```yaml
interaction_policy:
  maintain_attention_to_human: true
```

如果字段已经存在，则允许映射为一个简单的 commitment prior。

例如：

```text
maintain_attention_to_human = true
→ person commitment prior higher
```

但不要新增：

```yaml
person_commitment_weight: 0.73
chair_commitment_weight: 0.12
...
```

避免再次把行为系统做成权重表。

---

### 7. PTZ Integration

`RevisitController` 仍然是 PTZ 执行器。

P0008.1 只在已有 target switch / explore / timeout 决策之前增加一个仲裁步骤。

例如原来：

```text
new entity candidate
→ switched
```

改为：

```text
new entity candidate
→ Dwell Arbiter
    → HOLD
    或
    → SWITCH
```

原来：

```text
no curiosity target
→ explore
```

改为：

```text
no curiosity target
→ if current commitment still valid:
       HOLD
   else:
       RELEASE → explore
```

## Telemetry

必须增加 Commitment telemetry，用于验证行为而不是调参。

至少记录：

```text
commitment_start
commitment_hold
commitment_switch
commitment_release
```

每个 span 输出：

```text
entity
class
duration
avg_commitment
max_challenger_curiosity
decision_reason
```

Decision reason 建议限定：

```text
hold_role
hold_mission
hold_presence
switch_challenger
release_lost
release_stale
release_timeout
```

不要输出模糊自然语言原因。

## Success Criteria

1. `companion` Persona 下，持续存在的 person 不再因为 familiarity/freshness 下降而自动进入 explore。
2. person attention span 相比当前基线明显提升。
3. `explore + switched` 占比明显下降。
4. 新出现的高 curiosity 事件仍然能够打断当前目标。
5. 当前目标真正消失或持续无法确认时能够正常 RELEASE。
6. 不出现“死盯”：任何目标都必须存在明确的 release 条件。
7. `none` / 无 Mission 模式下，Runtime 仍能正常工作。
8. 所有 HOLD / SWITCH / RELEASE 都能从 telemetry 中解释。

## Validation Scenarios

不要先跑 24 小时。

先做三个短实验：

```text
Scenario A:
一个人在画面中持续 20 分钟
目标：验证 HOLD

Scenario B:
持续看人时，突然出现一个新物体
目标：验证 challenger 是否只有足够高时才 SWITCH

Scenario C:
正在观察的人离开
目标：验证 RELEASE → explore
```

三项通过后，再做自然客厅长测。

---

## Key Principle

> Curiosity competes for the next look.
> Commitment protects the current look.

P0008.1 的目标不是“让机器人盯人更久”。

它的目标是：

> **让 Runtime 第一次明确区分“探索新目标”和“维持当前关系”这两个不同的行为问题。**
